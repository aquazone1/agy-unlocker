# Промпт для установки на другом сервере

Скопируйте текст ниже в сессию агента, имеющего доступ к терминалу целевого сервера.
Ссылку своей подписки передайте отдельно через скрытый ввод или защищённый файл.

---

Установи и проверь на этом моём сервере agy-unlocker для Antigravity CLI.
Мне нужен доступ к моделям Google через мой личный аккаунт с действующей подпиской.
Используй собственный зарубежный прокси из моей подписки, без шлюза и ключа автора
стороннего анлокера. Выполняй команды самостоятельно; помощь запрашивай только
там, где требуется мой вход Google, недостающие секреты или доступ сервера.

Исходники проекта: https://github.com/aquazone1/agy-unlocker.
Вначале проверь содержимое: если там пока только README, рабочие скрипты ещё
не опубликованы. Попроси архив исходников с первого сервера, а не утверждай,
что установка из пустого репозитория состоялась.

Подтверждённая рабочая схема от 3 ноября 2026 года:

- Linux x86-64, Antigravity CLI 1.4.12, sing-box 1.13.18.
- Отдельная патченная копия CLI и локальный прокси VLESS TCP Reality.
- Проверенный узел находился в Нидерландах. Один немецкий узел соединялся,
  но генерация зависала. Это не означает, что необходимы именно Нидерланды:
  оценивай каждый выход реальным ответом модели, а не только геолокацией IP.
- Модель `gemini-3.8-flash-low` вернула `GOOGLE_OK`, процесс завершился с кодом 0.
- Исходная реализация патча: https://github.com/confeden/Antigravity,
  файл `src/patch_binary.rs`. Не путай с `loysger/Antigravity` — это другой клиент.

Порядок работы:

1. Проверь ОС, архитектуру, текущего пользователя, наличие Python 3.8+, GNU timeout,
   sing-box, systemd --user и установленного agy. Выясни, какие службы и прокси уже
   работают. Используй отдельный пользовательский сервис; сохрани существующие
   конфигурации перед изменениями. Если терминал изолирован от сети или systemd,
   сообщи точное ограничение и дай минимальные команды для настоящего SSH-сеанса.

2. Прочитай README и скрипты проекта. Установи отсутствующие зависимости из
   официальных источников с проверкой доступных контрольных сумм. Обеспечь наличие
   исходного CLI в `~/.local/bin/agy`. Для известной сборки 1.4.12 проверенный SHA-256:

   `1edfb30477447825f0aaa05fd9a91d82f9adf26686f41cd4f5c70b90abe383e8`

   Другая версия, архитектура или SHA требуют повторной проверки совместимости.
   Не удаляй проверку хеша и не подставляй новый хеш только ради прохождения защиты.

3. Создай патченную копию `~/.local/lib/antigravity-proxy/agy` через `patch.py`.
   Для указанного оригинала выполняется замена всех 9 вхождений байтов
   `ineligible` на `inexigible`. Длины одинаковы; размер бинарника не меняется.
   Оригинал не редактируется. Проверь точное обратное преобразование и сохранение
   прав исполнения через `check_patch.py`. Этот патч изменяет клиентскую обработку
   eligibility; он не создаёт подписку и не изменяет права аккаунта на сервере Google.

4. Получи мою подписку прокси через защищённый ввод. Сохрани её в
   `~/.config/antigravity-proxy/subscription`: каталог 700, файл 600.
   Не выводи содержимое подписки, UUID, пароли, полные URI, OAuth-токены или ключи
   в чат, логи и Git. Для выбора показывай только номер узла, страну и транспорт.
   Подписка может быть списком URI или его base64-представлением.
   Генератор проекта поддерживает только VLESS TCP Reality. Не используй его
   для Trojan, WebSocket или XHTTP без отдельной корректной реализации и проверки.
   Номер узла в новой подписке выбирай по её содержимому, а не автоматически 3.

5. Создай `~/.config/antigravity-proxy/config.json` для выбранного узла.
   Вход mixed HTTP/SOCKS должен слушать только `127.0.0.1:18047`.
   Сохрани проверку TLS и параметры Reality из подписки; не включай insecure TLS.
   Выполни `sing-box check` до запуска. Установи пользовательский сервис
   `antigravity-proxy.service` из проекта и включи его автозапуск. При необходимости
   используй `loginctl enable-linger` для соответствующего пользователя.
   Дождись открытия локального порта: немедленный curl после restart может застать
   сервис ещё неготовым. Не открывай неавторизованный прокси в интернет.

6. Установи обёртку `~/.local/bin/agy-google` из проекта. Она запускает отдельную
   патченную копию и задаёт для этого процесса HTTP_PROXY, HTTPS_PROXY, ALL_PROXY
   и варианты в нижнем регистре; NO_PROXY включает localhost и 127.0.0.1.
   Сохрани `GODEBUG=http2client=0` как часть проверенной схемы. Отдельного доказательства,
   что отключение HTTP/2 необходимо при любом маршруте, пока нет.
   При локальной установке проверь, что переменная AGY_PROXY не указывает на старый
   внешний прокси. Не прописывай общий системный прокси и не меняй DNS сервера.

7. Проверь OAuth-вход в мой аккаунт. Если его нет, запусти интерактивный
   `agy-google` и организуй поддерживаемый вход через браузер по SSH.
   Не копируй чужой аккаунт, не подставляй фиктивные токены и не публикуй мои токены.

8. Запусти реальные проверки:

   `python3 check.py`

   `python3 check_patch.py`

   Затем из живого SSH-терминала без перенаправления вывода:

   `timeout --foreground -k 3s 100s ~/.local/bin/agy-google --model gemini-3.8-flash-low --disable-slash-commands --print-timeout 60s -p 'Не используй инструменты. Ответь только: GOOGLE_OK'`

   Сразу сохрани код завершения. Успех — ответ `GOOGLE_OK` и код 0.
   Работающий порт, статус active, HTTP 200 на служебном API и список моделей сами
   по себе не подтверждают работоспособность генерации.

9. При ошибке прочитай журнал и определи стадию: инициализация CLI, OAuth,
   eligibility, отправка запроса, получение потока или завершение процесса.
   Для команд через timeout внутри скриптов нужен `--foreground`, иначе CLI может
   зависнуть на обращении к терминалу. Учитывай, что в этом режиме тайм-аут не
   гарантирует завершения всех дочерних процессов. Ошибку `trajectory not found`,
   возникшую после сигнала остановки, не принимай автоматически за первопричину.
   Упрощённый Python-запрос loadCodeAssist с `UNSUPPORTED_CLIENT` не доказывает,
   что официальный CLI устарел. strace и SIGQUIT могут быть недоступны.
   Проверяй по одной гипотезе, не удаляй историю диалогов без необходимости.
   Если нужно сравнить выходы прокси, сохрани старый config, меняй только узел и
   повторяй тот же запрос к той же модели.

10. Заверши работу отчётом: установленные версии, пути, имя сервиса, команда запуска,
    результат реального запроса и код завершения. Укажи, проверен ли автозапуск.
    Объясни откат: исходный `~/.local/bin/agy` сохранён; прокси отключается командой
    `systemctl --user disable --now antigravity-proxy`.
    Не объявляй успех без ответа модели. 9router для этой схемы не требуется;
    его возможную настройку считай отдельной задачей.

Сохрани воспроизводимые инструкции на новом сервере. Секреты и реальные
конфигурации держи вне репозитория. Обновление оригинального CLI автоматически
не обновляет патченную копию: новую версию сначала нужно проверить отдельно.
