# agy-unlocker

Локальный запуск Antigravity CLI с личным аккаунтом Google через собственный
зарубежный прокси. Ключ и шлюз стороннего анлокера не используются.

## Что проверено

3 ноября 2026 года на Linux x86-64: Antigravity CLI **1.4.12**, sing-box
**1.13.18**, VLESS TCP Reality через узел в Нидерландах. Модель
`gemini-3.8-flash-low` вернула `GOOGLE_OK`, процесс завершился с кодом `0`.
Другие модели, версии CLI и транспорты этим тестом не проверены.

## Принцип работы

1. `patch.py` создаёт отдельную копию `~/.local/bin/agy` в
   `~/.local/lib/antigravity-proxy/agy`. Девять вхождений `ineligible`
   заменяются на `inexigible`: клиент перестаёт распознавать соответствующие
   поля ответа проверки региона. Размер бинарника сохраняется, оригинал не меняется.
2. sing-box предоставляет локальный HTTP/SOCKS-прокси на `127.0.0.1:18047`.
3. `agy-google` задаёт прокси только запускаемому CLI и отключает HTTP/2
   через `GODEBUG=http2client=0`. Необходимость отключения HTTP/2 отдельно
   после получения рабочей схемы не проверялась.
4. CLI использует существующий OAuth-вход пользователя в Google.

Патч не создаёт подписку и не меняет права аккаунта на стороне Google.
Системный DNS, корневые сертификаты и TLS-перехват не используются.
Независимость здесь означает отсутствие шлюза автора анлокера; Google и
выбранный пользователем провайдер прокси остаются внешними сервисами.

Идея патча и его исходная реализация:
[confeden/Antigravity](https://github.com/confeden/Antigravity),
[src/patch_binary.rs](https://github.com/confeden/Antigravity/blob/main/src/patch_binary.rs).
Это **другой проект**, чем `loysger/Antigravity`; выводы о шлюзе последнего
не описывают анлокер Brent.

## Содержимое

- `patch.py` — воспроизводимое создание патченной копии; неизвестная версия отклоняется.
- `agy-google` — запуск CLI через локальный прокси.
- `proxy_config.py` — конфигурация из собственной локальной подписки; только VLESS TCP Reality.
- `systemd/antigravity-proxy.service` — пользовательский сервис sing-box.
- `check.py` — автономные проверки алгоритма и валидации входных данных.
- `check_patch.py` — проверка установленного оригинала и патченной копии.
- `diagnostics/` — сохранённые вспомогательные диагностические скрипты и их ограничения.

## Установка

Нужны Python 3.8+, sing-box, GNU timeout и пользовательский systemd.
Оригинальный CLI 1.4.12 должен находиться в `~/.local/bin/agy`.
Поддерживается только проверенный SHA-256:

```text
1edfb30477447825f0aaa05fd9a91d82f9adf26686f41cd4f5c70b90abe383e8
```

Из папки проекта:

```bash
python3 check.py
python3 patch.py
python3 check_patch.py
install -m 755 agy-google "$HOME/.local/bin/agy-google"
```

Подписку пользователь получает самостоятельно и сохраняет вне репозитория:
`~/.config/antigravity-proxy/subscription`, права файла `600`, каталога `700`.
Поддерживается обычный список URI или его base64-представление. Выберите номер
собственного узла; пример с номером `3` не означает, что он подходит любой подписке:

```bash
python3 proxy_config.py --node 3
sing-box check -c "$HOME/.config/antigravity-proxy/config.json"
```

Генератор намеренно не перезаписывает существующий `config.json`. При уже
работающей установке этот шаг пропустите. Для нового маршрута сначала сохраните
старую конфигурацию вне репозитория.

```bash
mkdir -p "$HOME/.config/systemd/user"
install -m 644 systemd/antigravity-proxy.service "$HOME/.config/systemd/user/"
systemctl --user daemon-reload
systemctl --user enable --now antigravity-proxy
sudo loginctl enable-linger "$USER"
```

Последняя команда позволяет пользовательскому сервису работать после выхода
из SSH и запускаться после перезагрузки. Активный сервис не гарантирует доступ
Google: проверять нужно реальным запросом к модели.

## Запуск и проверка

Интерактивно:

```bash
agy-google
```

Из SSH-терминала:

```bash
timeout --foreground -k 3s 100s agy-google \
  --model gemini-3.8-flash-low \
  --disable-slash-commands --print-timeout 60s \
  -p 'Не используй инструменты. Ответь только: GOOGLE_OK'
echo "Код завершения: $?"
```

Ожидается `GOOGLE_OK` и код `0`. В обёртках нужен `timeout --foreground`,
чтобы CLI мог работать с терминалом. В этом режиме timeout не гарантирует
завершение всех дочерних процессов.

## Что выяснено при диагностике

- Google поддерживает Германию и Нидерланды; IP США не обязателен.
  [Официальный список и требования к аккаунту](https://antigravity.google/docs/faq).
- Один проверенный немецкий узел установил соединение, но генерация не завершилась.
  После смены выхода на Нидерланды тот же тест прошёл. Это не доказывает
  неработоспособность всех немецких узлов или единственную причину зависания.
- Прокси без клиентского патча не устранил ошибку eligibility в нашей установке.
- `trajectory not found` в одном тесте появился после начала остановки по тайм-ауту.
- Зависание на `Initializing CLI store manager` воспроизводилось без доступа
  к foreground TTY; финальный успешный тест использовал `--foreground`.
- Сокращённый Python-запрос `loadCodeAssist` возвращал `UNSUPPORTED_CLIENT`.
  Его ответ нельзя считать вердиктом совместимости настоящего CLI.
- Снять стек через SIGQUIT не удалось; strace блокировался запретом ptrace.
- 9router не перенастраивался: подтверждён прямой запуск CLI через собственный прокси.

## Обновление и откат

Копия привязана к 1.4.12. После обновления оригинала не обходите проверку SHA-256:
сначала заново проверьте сигнатуры и совместимость. Автоматического перепатчивания нет.

Для исходного поведения запускайте `~/.local/bin/agy`. Для отключения прокси:

```bash
systemctl --user disable --now antigravity-proxy
```

Секреты, подписки, реальные конфигурации, OAuth-токены, журналы с личными данными
и бинарники в Git не включены. Файлы рабочей установки остаются вне проекта.
