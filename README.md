# agy-unlocker

Локальный запуск Antigravity CLI с личным аккаунтом Google через собственный
зарубежный прокси. Ключ и шлюз стороннего анлокера не используются.

## Что проверено

3 ноября 2026 года на Linux x86-64: Antigravity CLI **1.4.12**, sing-box
**1.13.18**, VLESS TCP Reality через узел в Нидерландах. Модель
`gemini-3.8-flash-low` вернула `GOOGLE_OK`, процесс завершился с кодом `0`.
Другие модели, версии CLI и транспорты этим тестом не проверены.

## Принцип работы

1. `patch.py` создаёт отдельную копию `~/.local/bin/agy` в
   `~/.local/lib/antigravity-proxy/agy-1.4.12`. Девять вхождений `ineligible`
   заменяются на `inexigible`: клиент перестаёт распознавать соответствующие
   поля ответа проверки региона. Размер бинарника сохраняется, оригинал не меняется.
2. `agy-google` по умолчанию ждёт HTTP-прокси на `127.0.0.1:10809` (любой
   SOCKS/HTTP-прокси с зарубежным выходом; в авторской установке это Xray
   из `~/proxy`). Альтернатива из исходной схемы: sing-box на `127.0.0.1:18047`
   (конфигурация — `proxy_config.py`), тогда задайте `AGY_PROXY=127.0.0.1:18047`.
   Адрес прокси произвольный: `AGY_PROXY=host:port`.
3. `agy-google` задаёт прокси только запускаемому CLI и отключает HTTP/2
   через `GODEBUG=http2client=0`. Необходимость отключения HTTP/2 отдельно
   после получения рабочей схемы не проверялась.
4. CLI использует существующий OAuth-вход пользователя в Google.

Патч не создаёт подписку и не меняет права аккаунта на стороне Google.
Системный DNS, корневые сертификаты и TLS-перехват не используются.
Независимость здесь означает отсутствие шлюза автора анлокера; Google и
выбранный пользователем провайдер прокси остаются внешними сервисами.

Идея патча и его исходная реализация:
[confeden/Antigravity](https://github.com/confeden/Antigravity),
[src/patch_binary.rs](https://github.com/confeden/Antigravity/blob/main/src/patch_binary.rs).
Это **другой проект**, чем `loysger/Antigravity`; выводы о шлюзе последнего
не описывают анлокер Brent.

## Содержимое

- `patch.py` — воспроизводимое создание патченной копии; неизвестная версия отклоняется.
- `agy-google` — запуск CLI через прокси; адрес задаётся переменной `AGY_PROXY`, по умолчанию локальный.
- `proxy_config.py` — конфигурация из собственной локальной подписки; только VLESS TCP Reality.
- `systemd/antigravity-proxy.service` — пользовательский сервис sing-box.
- `check.py` — автономные проверки алгоритма и валидации входных данных.
- `check_patch.py` — проверка установленного оригинала и патченной копии.
- `watchdog.py` + `systemd/agy-watchdog.timer` — автопроверка прокси и Gemini
  каждые 5 минут с переключением на рабочий узел подписки.
- `diagnostics/` — сохранённые вспомогательные диагностические скрипты и их ограничения.
- `MEDIA_RU.md` — промпт для генерации изображений и видео: картинки через CLI, видео — через браузерный Gemini по CDP (эталон — `story_google.py` в `tg_assistant`), проверено 5 ноября 2026.

## Как работает обход на уровне CLI

Antigravity CLI перед работой спрашивает у бэкенда, доступен ли сервис для
региона текущего аккаунта. Ответ содержит булевы поле/строки, в имени или
значении которых встречается байтовая последовательность `ineligible`
(ровно 9 вхождений в сборке 1.4.12). Клиент сравнивает их с ожидаемыми
признаками блокировки и при совпадении обрывает запуск с ошибкой
`Eligibility check failed ... not available in your location`.

`patch.py` заменяет эти 9 вхождений на `inexigible` (та же длина, размер
бинарника не меняется, оригинал не трогается). Патченный клиент больше не
находит в ответе знакомых признаков блокировки и считает регион допустимым:

- CLI: `ответ проверки → сравнение строк → inexigible ≠ ожидаемое поле →
  блокировка не распознана → запуск продолжается`.
- Патч снимает только **клиентскую** проверку. Серверная часть по-прежнему
  видит IP выхода, поэтому зарубежный прокси обязателен: без него запросы
  модели уходят с локального IP и отсекаются на стороне Google.
- Автообновление CLI заменило бы патченную копию свежей непатченной
  сборкой — обёртка выставляет `AGY_CLI_DISABLE_AUTO_UPDATE=1`, а сторож
  (`watchdog.py`) пересоздаёт патч, если проверка `check_patch.py` не прошла.

Сами запросы к модели идут по HTTPS через прокси из переменных окружения;
TLS не вскрывается, трафик не расшифровывается.

## Вход в аккаунт Google (логин)

Никакого отдельного ключа или токена не нужно: CLI использует обычный
OAuth-вход Google в браузере.

Требования:

- Google-аккаунт с доступом к Antigravity. Проверить можно в браузере:
  <https://antigravity.google> — сервис должен открываться без ошибки региона.
  Список поддерживаемых стран: <https://antigravity.google/docs/faq>.
- Регион аккаунта и выход прокси должны быть совместимы: проверенная связка —
  аккаунт любой поддерживаемой страны + выход прокси в Нидерландах или
  Германии. IP США не обязателен.

Порядок входа:

1. Выполните интерактивный запуск один раз — обязательно в настоящем
   терминале, не через pipes:

   ```bash
   agy-google
   ```

2. CLI выведет ссылку для входа (OAuth). Откройте её в браузере, войдите в
   свой Google-аккаунт и подтвердите доступ. После редиректа CLI получит
   токен сам и сохранит его в домашнем каталоге пользователя.
3. На сервере без браузера: либо откройте ссылку на локальной машине,
   выполнив вход при живом SSH-соединении (токен сохранится на сервере,
   потому что callback возвращается на порт CLI), либо выполните вход на
   машине с браузером и перенесите каталог с credentials на сервер той же
   версией CLI.
4. Проверьте вход реальным запросом — ожидается `GOOGLE_OK` и код `0`:

   ```bash
   timeout --foreground -k 3s 100s agy-google \
     --model gemini-3.8-flash-low \
     --disable-slash-commands --print-timeout 60s \
     -p 'Не используй инструменты. Ответь только: GOOGLE_OK'
   echo "Код завершения: $?"
   ```

Если вместо ответа появляется `Eligibility check failed`, причины по
убыванию вероятности: прокси не работает или выдаёт неподходящий регион
(проверьте `curl -x http://$AGY_PROXY https://api.ipify.org`), автообновление
испортило патч (проверьте `python3 check_patch.py`), аккаунт не имеет
доступа к Antigravity.

### Ошибка входа: `127.0.0.1:10809: connect: connection refused`

Если при входе появляется:

```text
token exchange failed: Post "https://oauth2.googleapis.com/token": proxyconnect tcp: dial tcp 127.0.0.1:10809: connect: connection refused
```

CLI не смог подключиться к локальному прокси: на указанном адресе нет
доступного слушателя. До обмена токена с Google запрос не дошёл.
Возможная причина — несовпадение портов: обёртка `agy-google` по умолчанию
использует `10809` (Xray), а sing-box из `proxy_config.py` слушает `18047`.

Проверьте порты на той машине, где запущен CLI:

```bash
ss -ltnp '( sport = :10809 or sport = :18047 )'
systemctl --user status antigravity-proxy.service
```

Если sing-box слушает `127.0.0.1:18047`, проверьте соединение и повторите вход:

```bash
curl --max-time 20 --proxy http://127.0.0.1:18047 --noproxy '' \
  --output /dev/null --write-out 'HTTP %{http_code}\n' \
  --data 'grant_type=authorization_code' https://oauth2.googleapis.com/token
AGY_PROXY=127.0.0.1:18047 agy-google
```

Для этой проверки ожидается HTTP `400`: Google получил запрос, но в нём
намеренно нет OAuth-кода и данных клиента. Это проверка соединения, не входа.
Если нужный порт не слушается, сначала запустите соответствующий прокси;
для настроенного sing-box: `systemctl --user start antigravity-proxy.service`.

Чтобы сохранить адрес для последующих запусков, добавьте
`export AGY_PROXY=127.0.0.1:18047` в `~/.bashrc` (для Bash) и откройте новый
терминал. Разовая переменная действует только на один запуск. Также можно
изменить порт по умолчанию в установленном `~/.local/bin/agy-google`, но
повторная установка обёртки из репозитория перезапишет эту правку.
Для прокси на другой машине задайте её адрес: `127.0.0.1` всегда означает
машину, на которой работает CLI.

## Установка

Нужны Python 3.8+, GNU timeout и пользовательский systemd; sing-box — только
для альтернативного варианта прокси через `proxy_config.py`. Оригинальный CLI
1.4.12 должен находиться в `~/.local/bin/agy`.
Поддерживается только проверенный SHA-256:

```text
1edfb30477447825f0aaa05fd9a91d82f9adf26686f41cd4f5c70b90abe383e8
```

Из папки проекта:

```bash
python3 check.py
python3 patch.py
python3 check_patch.py
install -m 755 agy-google "$HOME/.local/bin/agy-google"
```

Подписку пользователь получает самостоятельно и сохраняет вне репозитория:
`~/.config/antigravity-proxy/subscription`, права файла `600`, каталога `700`.
Поддерживается обычный список URI или его base64-представление. Выберите номер
собственного узла; пример с номером `3` не означает, что он подходит любой подписке:

```bash
python3 proxy_config.py --node 3
sing-box check -c "$HOME/.config/antigravity-proxy/config.json"
```

Генератор намеренно не перезаписывает существующий `config.json`. При уже
работающей установке этот шаг пропустите. Для нового маршрута сначала сохраните
старую конфигурацию вне репозитория.

```bash
mkdir -p "$HOME/.config/systemd/user"
install -m 644 systemd/antigravity-proxy.service "$HOME/.config/systemd/user/"
systemctl --user daemon-reload
systemctl --user enable --now antigravity-proxy
sudo loginctl enable-linger "$USER"
```

Последняя команда позволяет пользовательскому сервису работать после выхода
из SSH и запускаться после перезагрузки. Активный сервис не гарантирует доступ
Google: проверять нужно реальным запросом к модели.

## Центральный прокси на роутере

Патч бинарника остаётся на каждом клиенте: он меняет обработку ответа
проверки региона внутри CLI, и роутер не может подменить байты в TLS-трафике
без перехвата сертификатов. На роутер выносятся только прокси и подписки.

На роутере один раз:

```bash
python3 proxy_config.py --node 3 --listen 0.0.0.0
sing-box check -c "$HOME/.config/antigravity-proxy/config.json"
systemctl --user enable --now antigravity-proxy
```

`--listen 0.0.0.0` открывает порт `18047` всей сети. Ограничьте его
брандмауэром адресами своих серверов, например:

```bash
sudo iptables -A INPUT -p tcp --dport 18047 ! -s 10.0.0.0/24 -j DROP
```

Смена узла или подписки — только на роутере:

```bash
# отредактировать ~/.config/antigravity-proxy/subscription
python3 proxy_config.py --node 2 --listen 0.0.0.0 --force
systemctl --user restart antigravity-proxy
```

На каждом сервере-клиенте:

```bash
python3 patch.py
install -m 755 agy-google "$HOME/.local/bin/agy-google"
echo 'export AGY_PROXY=192.168.1.1:18047' >> "$HOME/.profile"  # адрес роутера
```

Проверка с клиента та же, что ниже: `GOOGLE_OK` и код `0`.

## Запуск и проверка

Интерактивно:

```bash
agy-google
```

Из SSH-терминала:

```bash
timeout --foreground -k 3s 100s agy-google \
  --model gemini-3.8-flash-low \
  --disable-slash-commands --print-timeout 60s \
  -p 'Не используй инструменты. Ответь только: GOOGLE_OK'
echo "Код завершения: $?"
```

Ожидается `GOOGLE_OK` и код `0`. В обёртках нужен `timeout --foreground`,
чтобы CLI мог работать с терминалом. В этом режиме timeout не гарантирует
завершение всех дочерних процессов.

## Что выяснено при диагностике

- Google поддерживает Германию и Нидерланды; IP США не обязателен.
  [Официальный список и требования к аккаунту](https://antigravity.google/docs/faq).
- Один проверенный немецкий узел установил соединение, но генерация не завершилась.
  После смены выхода на Нидерланды тот же тест прошёл. Это не доказывает
  неработоспособность всех немецких узлов или единственную причину зависания.
- Прокси без клиентского патча не устранил ошибку eligibility в нашей установке.
- `trajectory not found` в одном тесте появился после начала остановки по тайм-ауту.
- Зависание на `Initializing CLI store manager` воспроизводилось без доступа
  к foreground TTY; финальный успешный тест использовал `--foreground`.
- Сокращённый Python-запрос `loadCodeAssist` возвращал `UNSUPPORTED_CLIENT`.
  Его ответ нельзя считать вердиктом совместимости настоящего CLI.
- Снять стек через SIGQUIT не удалось; strace блокировался запретом ptrace.
- 9router не перенастраивался: подтверждён прямой запуск CLI через собственный прокси.

## Автоматический сторож

`watchdog.py` по таймеру (раз в 5 минут) выполняет три проверки:

1. **Прокси** — `proxy_manager.py ensure`: если локальный прокси мёртв или
   Google через него не отвечает, менеджер сам тянет подписку и поднимает
   лучший живой узел.
2. **Патч** — `check_patch.py`: если автообновление CLI испортило патченную
   копию, патч пересоздаётся из текущего оригинала.
3. **Gemini** — реальная проба `agy-google` (модель `gemini-3.8-flash-low`,
   ожидается `GOOGLE_OK`; чаще чем раз в 10 минут не повторяется). Если прокси
   жив, а Gemini отвечает ошибкой eligibility, форсируется полный перебор
   узлов и смена выхода (`proxy_manager.py up`).

Установка:

```bash
install -m 644 systemd/agy-watchdog.service systemd/agy-watchdog.timer \
  "$HOME/.config/systemd/user/"
systemctl --user daemon-reload
systemctl --user enable --now agy-watchdog.timer
```

Журнал: `~/.local/state/agy-watchdog.log`. Сервис предполагает, что
репозиторий лежит в `~/agy-unlocker` (путь задан в `ExecStart` через `%h`).
Сторож рассчитан на связку с личным Xray из `~/proxy` (порты `10808`/`10809`),
а не с sing-box из ранней версии инструкции.

## Обновление и откат

Копия привязана к 1.4.12. После обновления оригинала не обходите проверку SHA-256:
сначала заново проверьте сигнатуры и совместимость. Автоматического перепатчивания нет.

Обёртка задаёт `AGY_CLI_DISABLE_AUTO_UPDATE=1`: иначе CLI может заменить
патченную копию новой непатченной сборкой, и следующий запрос снова завершится
ошибкой eligibility. После запуска проверяйте `python3 check_patch.py`.

Для исходного поведения запускайте `~/.local/bin/agy`. Для отключения прокси:

```bash
systemctl --user disable --now antigravity-proxy
```

Секреты, подписки, реальные конфигурации, OAuth-токены, журналы с личными данными
и бинарники в Git не включены. Файлы рабочей установки остаются вне проекта.

Версионная копия `agy-1.4.12` отделена от прежнего файла `agy`: уже запущенный
старый CLI может обновлять прежний файл независимо от новой обёртки.
